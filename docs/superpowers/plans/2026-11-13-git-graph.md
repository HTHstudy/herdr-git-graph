# Git Graph for Herdr Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Herdr side-panel tab "Graph" that recreates VS Code Git Graph: lane graph, inline commit details, a reusable diff pane, every right-click git action, and the full top bar.

**Architecture:** One mod `git-graph` with roles chosen by `props()` (panel / diff pane / menu popup / dialog), like herdr-nvim. All git knowledge (argv building, output parsing, lane layout, menus, dialogs, diff parsing) lives in pure ES modules under `mods/git-graph/lib/` that import nothing from `herdr`/`gpui-kit`, so `node --test` runs them against a real fixture repo. UI modules under `mods/git-graph/ui/` are thin and verified with `herdr-app check` + `herdr-app shot`. A clone of the shipped `tabs` mod (`git-graph-tabs`) adds the Graph button.

**Tech Stack:** Herdr gpui-kit JS (gpui-shell), `herdr` module, Node 24 `node:test` for pure modules, git CLI.

**Spec:** `docs/superpowers/specs/2026-11-13-git-graph-design.md`

## Global Constraints

- No HTML/CSS/web view/Node APIs/`setTimeout` in mod code; use `cx.timer`, `cx.spawn`; never keep a `cx`.
- `lib/*.js` must not import `herdr`, `gpui-kit`, `gpui-base`, or `node:*` (they run in both Herdr and Node).
- All colors from `theme()` names; lane colors cycle `ansi1..ansi6`.
- Every git read uses `--no-optional-locks -c core.fsmonitor=false` (READ prefix, as in shipped `changes`).
- Destructive actions (Drop, Reset --hard, Delete Branch, Delete Remote Branch, Delete Tag, Reset uncommitted, Clean, Drop Stash, any force) always go through a confirm dialog.
- Fetch = `git fetch --all --prune` (was no prune; changed 2026-11-18 so branches deleted on the server disappear).
- First load 300 commits; +300 when scrolled to the end.
- Copy-to-clipboard via `cx.write_to_clipboard(text)`.
- Diff pane draws its own lines (per-line +/− backgrounds) instead of `EditorState`, which can't color whole lines; no token-level syntax highlighting in this version.
- `herdr-app` CLI is `/Applications/Herdr.app/Contents/MacOS/Herdr` (not on PATH); referred to below as `$HA`.
- A mod is done only when `$HA check <mod folder>` passes.
- Menu labels are exactly the spec's (English, Git Graph wording).

## Review Focus

1. **Detached HEAD / empty repo / repo with no remotes** — panel still renders, menus omit current-branch and remote items; a fresh `git init` with zero commits shows "No commits yet", not an error. (Tests in Task 3 and Task 5.)
2. **Branch/tag names with `/`, unicode, and paths with spaces** — parsing and argv building keep them intact (argv arrays, never shell strings). (Tests in Task 3 and Task 5.)
3. **Repo changes while a dialog is open or an action runs** — action runs against the hash/name captured when the menu opened; second action on same repo is refused with a toast while one runs. (Test in Task 5 for captured target; manual check in Task 11.)
4. **Huge repos (≥10k commits, wide merges)** — paging stays at 300/page, lanes cap visually (lanes beyond 12 collapse into the last column) and scrolling uses `v_virtual_list`. (Test in Task 4 for lane cap.)
5. **Focus switches to a non-repo folder or a remote space mid-load** — stale results are discarded (context key check, as in `changes`). (Manual check in Task 7.)

### Task 4: Lane layout (`lib/lanes.js`)

**Files:**
- Create: `mods/git-graph/lib/lanes.js`, `test/lanes.test.mjs`

**Interfaces:**
- Consumes: `Commit`, `Stash` from Task 3.
- Produces:
  - `Row = {kind: "commit"|"stash"|"uncommitted", hash: string, lane: number, color: number, lines: Line[], commit?: Commit, stash?: Stash}`
  - `Line = {from: number, to: number, color: number, half: "top"|"bottom"}` — `top` draws from row top at lane `from` to row middle at lane `to`; `bottom` from middle at `from` to bottom at `to`. Straight pass-through lanes appear as a `top` and a `bottom` line with `from===to`.
  - `MAX_LANES = 12` — lanes ≥ 12 are drawn at lane 11.
  - `layoutGraph(commits: Commit[], stashes: Stash[], headHash: string|null, uncommitted: boolean): Row[]` — inserts each stash immediately above its `base` commit (stash parent = base only); prepends an `uncommitted` row (hash `"*"`, parent = `headHash`) when `uncommitted`. `color = lane % 6` for the lane where the branch started (keep a lane's color while it lives).
  - Algorithm: classic active-lanes list. Each row: lane = first index holding this hash, else first empty, else push. Other indexes holding the same hash merge into it (top lines from those lanes to this lane, then freed). First parent takes this lane; other parents take an existing lane already expecting them, else the first empty/new lane (bottom line from this lane to that lane). Parents not in the loaded set still occupy a lane to the bottom of the list.

- [ ] **Step 1: Tests:**
  - linear `[c3→c2→c1]`: all `lane:0`, middle row has one `top` and one `bottom` line `{from:0,to:0}`.
  - merge `M(parents A,B)`, `B(parent A)`, `A`: M lane 0 with bottom lines to 0 and 1; B lane 1 with a `top` line `{from:1,to:1}` and bottom `{from:1,to:0}`; A lane 0.
  - stash: stash row sits directly above its base, `kind:"stash"`, lane ≠ base's lane.
  - uncommitted: first row `kind:"uncommitted"`, lane 0, `bottom` line to HEAD's lane.
  - fixture smoke: layout of the fixture's parsed log + stashes has no row with `lane ≥ MAX_LANES` and every commit appears once.
  - lane cap: 20 parallel heads → no `lane > 11`.
